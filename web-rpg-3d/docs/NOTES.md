# 3D 版與劇本、2D 版的出入與取捨

## 1. 內容：與 2D 版完全相同

3D 版直接載入 `web-rpg/js/data/` 的資料檔，所以**對白、旁白、過場、任務、物品、配方、商店、遭遇、葉帖、教學、章末文字與 2D 版逐字相同**。
劇本（`web-rpg/docs/script/ch00-prologue.md`）與 2D 版之間既有的出入，記錄在 `web-rpg/docs/IMPLEMENTATION_NOTES.md`，3D 版沒有新增劇情上的改動，也沒有改寫劇本。

## 2. 3D 版新增或改變的部分（都屬於呈現，不影響規則）

| 項目 | 2D 版 | 3D 版 | 理由 |
|---|---|---|---|
| 移動 | 一次一格、四方向 | 連續移動、相對鏡頭、類比搖桿 | 3D 第三人稱一格一格走手感很差。每跨進新的一格仍呼叫同一個 `onPlayerStep`，傳送、觸發、硫氣孔、自動遭遇的判定與 2D 相同 |
| 互動對象 | 面向的那一格 | 先找面向那一格；沒有就找前方 1.75 格內最近的，並在畫面上提示 | 連續移動時很難剛好正對一格 |
| 地形高度 | 平面 | 由 `web-rpg-3d/js/layouts3d.js` 設計：階梯池三層（約 0／1.3／2.6）、岩格隆起成崖、池底下陷、脈橋下是深谷 | 資料檔只有平面字元格；劇本描述「熱柱上方的階梯溫泉池」「脈橋」由這裡具體化 |
| 脈橋 | `=` 格 | 橋面範圍內的草與花也畫成橋上的植物（站在橋上）；地圖南北外側延伸成開闊峽谷 | 2D 地圖中橋上有 `"`、`f` 地面格，若照字面會在深谷中立起一根根土柱 |
| 浮基小棚 | `H` 方塊＋門 | 根腳托起的平台、犢皮膜牆、靛葉穹頂；門朝 `D` 格 | ip-bible 的建築語彙 |
| 遭遇畫面 | 面板＋小圖 | 同一套面板，舞台區是 3D 診療現場 | 規則與文字不變 |
| 葉帖、調劑、對話、選單、章末 | DOM 介面 | 同一套 DOM 介面，疊在 3D 之上 | 統一的犢皮手稿風 |
| 標題 | 靜態標題圖 | 霧階池站的即時 3D 空拍 | — |

## 3. 取捨

- **造型以程式生成**：人物、生物、植物、建物全部是基本幾何體組合（膠囊、球、旋轉體、管線），沒有外部模型或骨架動畫檔。行走、待機、轉身是程式驅動的肢體擺動。可辨識，但不是手工建模的精細度。
- **沒有後製泛光（bloom）**：生物發光用加法混合的光暈貼片與自發光材質模擬，避免手機上多一次全螢幕繪製。
- **陰影只在高畫質**：低畫質關閉陰影與霧氣面片，點光源從 6 盞降到 2 盞。
- **過場鏡頭**：劇本的過場指令是 2D 的「鏡頭移到某格」，3D 版改成把鏡頭焦點平滑移過去，不另做電影式運鏡。
- **導管洞**：洞壁做成約 1.5 單位高的矮牆、沒有洞頂，鏡頭偏俯視。窄道只有一格寬，做成完整洞頂會讓鏡頭無處可放。
- **存檔與 2D 版共用同一組鍵**：同一網域下兩版可以互讀存檔（存檔內容只有邏輯狀態，與呈現無關）。

## 4. 遊玩時間

**估算，不是實測。** 依 2D 版的估算工具（`node web-rpg/tools/estimate-playtime.js`：對白字數、步行格數、遭遇回合換算）：

- 只走主線約 78 分鐘，含全部支線約 96 分鐘，誤差 ±20%。
- 3D 版的對白、遭遇、調劑與 2D 版相同；步行速度約每秒 4.2 格（2D 版估算用每秒 3.36 格），但 3D 視角下找路、轉鏡頭、看場景會多花時間，估計整體多 5–10 分鐘。
- 沒有真人計時的完整遊玩紀錄；自動測試的耗時受軟體繪圖拖慢，不能當作遊玩時間。

### 量測

初次載入（`index.html` 引用的全部檔案＋13 個資料檔＋標題圖）：50 個檔案、約 1.42 MB，gzip 後約 0.57 MB；其中 three.js 543 KB、共用引擎 257 KB、資料 219 KB、3D 呈現層約 160 KB。

幀率（`node web-rpg-3d/tests/measure.js`；SwiftShader 是 CPU 軟體繪圖，**不代表實機**，只能當相對比較）：

| 情境 | 高畫質 | 低畫質 |
|---|---|---|
| 桌機 1280×720，霧階池站 | 約 2 fps | 約 6 fps |
| 桌機 1280×720，首領遭遇 | 約 3 fps | 約 6 fps |
| 模擬手機 390×844（DPR 3），霧階池站 | 約 2 fps | 約 15 fps |
| 模擬手機 390×844（DPR 3），首領遭遇 | 約 4 fps | 約 17 fps |

與 GPU 無關、可直接參考的繪製量（霧階池站，合併後）：高畫質約 150 次 draw call（含陰影 pass）、約 17 萬個三角形；低畫質地形網格減為四分之一，約 5.5 萬個三角形。
實體 GPU 與實體手機上的幀率**沒有量到**（這個環境沒有）。
